A test found a real bug. The configuration ignored unknown settings without a word, so a typo dropped the limit and it never applied. The tool would run, look healthy, and never fire. An unknown setting now stops it at startup and lists the valid ones.
How it works

A problem must persist across three checks before the tool raises anything, and recovery across five before it stands down. Convincing it a fault has ended should be harder than convincing it one began. Alarms fire on changes only, so a long outage produces two lines instead of two hundred.

I designed for testing first. Probes never raise, so an unreachable host is just data. The alarm logic holds no clock and does no input or output, which is why twenty minutes of behaviour can be exercised in a millisecond.

It exits non-zero when something is wrong, so it works as a check after a change, not only as a dashboard.

How it was done

I built this in Linux network namespaces, with real interfaces, real routing and real queueing, so I could reproduce the fault and measure it.

The switch held everything in one deep queue, so voice waited behind bulk data in the same buffer. I replaced it with HTB class-based shaping, used u32 filters matching DSCP EF to steer voice into a priority class, and bonded the two uplinks with 802.3ad LACP.

before rtt min/avg/max/mdev = 128.357/152.524/165.103/9.248 ms after rtt min/avg/max/mdev = 20.022/ 20.029/ 20.039/0.005 ms

Every mechanism maps onto vendor configuration. The shaping classes become a policy-map, the filters become match dscp ef, the bond becomes EtherChannel. The work transfers to Cisco kit.

How it works

Courses that check answers by comparing text teach people to produce the expected words instead of working code. Marking real submissions normally needs a server, which means hosting, cost, and an account before a learner writes a line.

It runs Python in the browser through Pyodide, compiled to WebAssembly, and marks each submission against a hidden test suite. Course content is data, held separately from the engine, so adding material needs no code changes. Around 900 lines of plain JavaScript, no framework.

How it was done

The branch reached head office through a WireGuard site-to-site tunnel, with nftables enforcing policy at the branch edge. I confirmed the saturation against interface counters, then applied a time-based bandwidth policy that caps backup traffic inside business hours and releases it outside them.

I shaped backup throughput from 20.7 Mbps down to 1.31 Mbps during the day. The backup still finishes. It stops competing with the people trying to work.

“My settings disappeared”The policy is linked and switched on, and it is. The cause is a permission change that stops the computer reading the policy at all.
“It locks me out when I'm not even here”The account is locked and resetting the password changes nothing. An old saved password is retrying in the background from another machine.
“Nobody at the site can log in”The server is up and browsing the web fine. It is looking up names on the internet instead of its own directory, which is exactly why browsing still works.
Not finished yet. I have written the build scripts, the health check and the fault injection, and CI checks every script on each push. I have not run the full build against live virtual machines yet, so this page carries no measured results for it. None will appear until I have them.
How it was done

PowerShell creates the forest, DNS, DHCP, the directory tree, the group model, policies and delegation, and every script is safe to re-run. There is no click-through in the build and no screenshot of a wizard in the repository. A network that exists only as remembered clicks cannot be rebuilt under pressure.

The health check answers 27 questions about the domain with pass, warn or fail and exits non-zero on any failure. The failures that cost the most time stay silent: a missing reverse zone, an unauthorised DHCP server, a share that never came back after a reboot. None of them announce themselves.

I gave the helpdesk three explicit permissions on one part of the directory. The usual shortcut adds people to a group that hands them everything.

Software

A rendering pipeline kept taking the whole machine down. I made it check itself before it runs.

Batch image pipeline, one graphics card, 12 GB of memory

How it works

Two jobs overlapping meant an out-of-memory failure that froze the machine. Bad output from an early stage wasted time on every stage after it.

A preflight check validates the environment, confirms the models are present and checks free memory before I submit anything. Jobs run one at a time, so stages never overlap. A quality gate scores each stage's output and rejects failures before they reach the next one.

I built one of the quality measures, tested it against known inputs, found it could not separate the cases it was meant to catch, and deleted it. Shipping it would have given me a check that fires on everything. Knowing what to leave out is the part of this I am most confident about.
